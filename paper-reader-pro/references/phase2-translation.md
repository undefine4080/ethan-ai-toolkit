# 阶段二：论文全文翻译

阶段二将 PDF 论文转化为高质量的中文 HTML 版本，包含三栏布局（目录 | 译文正文+图表 | 注解）。

## 工作目录结构

```
<论文所在目录>/
  <论文文件名>.pdf
  raw/
    manuscript.md       # 原文逐字提取稿
    figures/            # 所有图表截图
    figure_map.json     # 图片位置元数据
  translated/
    manuscript.md       # 高质量中文译文
    glossary.md         # 术语表
    review_report.md    # 最终审查报告
  <论文文件名>-cn.html   # 最终输出的中文 HTML
```

论文所在目录由阶段一确定（即用户提供的 PDF 文件所在的目录）。

## 整体流程

阶段二包含五个子步骤，按顺序执行。每个子步骤由一个独立的 Agent 完成。

**重要：每完成一个子步骤，必须停下来向用户展示产物摘要，等待用户确认后再继续下一步。** 这样用户可以在每一步检查中间产物，而不是等到最后发现方向偏了。

## 第 1 步：文字提取

### 目标
从 PDF 中逐字逐句提取原文，连同图片信息一起输出为结构化的 markdown 文件。

### Agent 任务

启动一个独立的 Agent，完成以下工作：

1. **创建目录**：在论文目录下创建 `raw/` 和 `raw/figures/` 目录

2. **文字提取**：
   - 使用 `pdfplumber` 逐页提取文字
   - 自动检测每页是单栏还是双栏布局，双栏按阅读顺序重组（先左栏后右栏）
   - 保留原文的段落结构、标题层级
   - 数学公式区域：尝试提取 LaTeX 源码；无法提取的用 `[FORMULA]` 占位标记

3. **图片提取**：
   - 使用 PyMuPDF（fitz）提取每页的嵌入图像
   - **智能筛选**：用与阶段一相同的筛选逻辑（宽度>35% 或面积>15%），只保留学术图表
   - 对每个保留的图片，精确定位边界框，用 2.5 倍缩放渲染为高清 PNG
   - 保存到 `raw/figures/` 目录，命名格式 `page{页码}_fig{序号}.png`
   - 同时将整页渲染为 `raw/figures/page{页码}_full.png`（作为备用参考）

4. **生成元数据**：
   - 创建 `raw/figure_map.json`，记录每个图片的：
     - 文件名、所在页码、图片尺寸
     - caption 文字（从页面文字中提取对应的图注）
     - 在 markdown 中的引用标记

5. **生成原文章节**：
   - 写入 `raw/manuscript.md`
   - 每个图片位置插入标记 `[FIGURE: pageX_figY]`
   - 如果有对应的 caption，紧跟 `> **图 X：** caption 文字`
   - **表格和图表区域的处理**（核心规则）：
     - pdfplumber 从表格区域提取的文字无法保持表格格式，会被摊平成散乱数字行，毫无可读性
     - 因此：如果某个表格或图表已通过 PyMuPDF 截取为图片并记录在 `figure_map.json` 中，**禁止**将 pdfplumber 从该区域提取的表格单元格文字写入 `manuscript.md`
     - 表格/图表的标题文字（如 "Table 3: Zero-shot Evaluations..."）可以保留，但标题之后的表格数据行一律省略
     - 图片的 caption 保留并写入 `manuscript.md`，但图表内部的轴标签、图例、数据标签等碎片文字不提取
     - 反正：图片中已包含所有这些信息，文本版本只会制造垃圾
   - 图表内嵌的轴标签、图例文字（如 "Perplexity (log scale)"、"6 × 100"、"102 103 104 105" 等）**不提取**——它们脱离图表上下文毫无意义

6. **Agent 完成后的检查清单**：
   - `raw/manuscript.md` 是否存在且有完整内容？
   - `raw/figures/` 中是否有图片文件？
   - `raw/figure_map.json` 是否存在？
   - 段落的完整性：原文的开头和结尾是否都提取到了？
   - 图片数量和论文大致是否一致？
   - **垃圾表格文本检查**：逐个检查 `[FIGURE: ...]` 标记后的段落，是否混入了摊平的表格数据（连续的短数字行、模型名列表、表格头碎片如 "Model Token. Pile ppl ↓ acc ↑" 等）？如有，手动删除

### 注意事项
- 如果 PDF 是扫描版（提取文字极少），需要使用 OCR（pytesseract + pdf2image）
- 公式密集的论文（如数学、物理），要特别注意公式区域的完整性
- 提取完成后，Agent 应向用户报告：总页数、总段数、总图片数、提取的公式数

## 第 2 步：翻译

### 目标
将原文逐段翻译为高质量中文，遵循翻译质量手册的标准。

### Agent 任务

启动一个独立的 Agent，必须读取 `references/translation-guide.md` 作为翻译标准，完成以下工作：

1. **准备工作**：
   - 读取 `raw/manuscript.md`
   - 读取 `references/translation-guide.md`（翻译质量手册）

2. **建立术语表**：
   - 快速扫描全文，识别反复出现的专业术语
   - 为每个术语确定中文译法
   - 写入 `translated/glossary.md`
   - 术语表格式：
     ```
     | 英文术语 | 中文译法 | 备注 |
     |---------|---------|------|
     | selective state space model | 选择性状态空间模型 | 本文核心概念 |
     ```

3. **逐段翻译**：
   - 保持原文的段落结构，一段对一段
   - 公式（`$...$`、`$$...$$`）、引用（`[1]`、`(Author et al. 2020)`）、图片标记（`[FIGURE: xxx]`）原样保留
   - 图片的 caption 翻译为中文，保留 `[FIGURE: xxx]` 标记

4. **自检**：
   - 翻译完成后通读一遍
   - 检查术语一致性
   - 检查有无遗漏段落

5. **输出**：
   - `translated/manuscript.md`：逐段对应的译文
   - `translated/glossary.md`：术语表

6. **Agent 完成后的检查清单**：
   - 译文的段落数是否与原文一致？
   - 所有 `[FIGURE: xxx]` 标记是否保留？
   - 公式和引用是否原样保留？
   - 粗略阅读前几段，译文是否符合翻译质量标准？

## 第 3 步：生成 HTML

### 目标
将译文和图片组装成三栏布局的 HTML 文件，严格遵循"纸质论文阅读体验"设计规范。

### 设计规范

**HTML 构建 Agent 必须读取 `references/design.md`**，该文档定义了完整的 UI 设计标准：
- 字体体系（Crimson Pro + Noto Serif SC 衬线正文，Atkinson Hyperlegible UI）
- 配色系统（暖白纸张 + 学术暗红强调色，亮/暗双主题）
- 纸张纹理质感（SVG 噪声叠加）
- 三栏布局（毛玻璃侧栏 + 纸张投影正文区）
- 所有组件样式（标题栏、目录、图片、引用、表格、注解卡片等）
- 响应式断点和打印样式
- Agent 执行检查清单

参考实现见 `assets/paper-template.html`，这是基于设计规范生成的完整 HTML，可直接参考其中的 CSS 变量、组件结构和 JavaScript 交互逻辑。

### Agent 任务

启动一个独立的 Agent，完成以下工作：

1. **读取输入**：
   - `translated/manuscript.md`（译文）
   - `raw/figure_map.json`（图片元数据）
   - `references/design.md`（UI 设计规范）
   - `assets/paper-template.html`（参考实现）
   - `assets/smooth-white-plaster-wall.jpg`（纸张纹理图片，必须复制到输出目录）

2. **解析译文结构**：
   - 从 markdown 中提取标题层级（H1、H2、H3）
   - 为每个标题生成 ID（用于目录锚点）
   - 为每个段落生成唯一 ID（格式 `p-{section}-{seq}`，用于后续注解锚定）

3. **处理图片引用**：
   - 将 `[FIGURE: pageX_figY]` 替换为实际的 `<img>` 标签
   - 图片路径使用相对路径，指向 `raw/figures/pageX_figY.png`
   - 将翻译后的 caption 包装在 `<figcaption>` 中

4. **处理公式**：
   - 确保所有 `$...$`、`$$...$$` 公式包裹在正确的环境中，KaTeX 会自动渲染
   - 对于 `[FORMULA]` 占位符（第1步未能提取的），保留标记并添加说明

5. **生成目录**：
   - 遍历所有 H2 和 H3 标题
   - 生成嵌套的 `<li><a href="#section-id">标题</a></li>`
   - H3 添加 `toc-h3` class 实现缩进

6. **占位注解区域**：
   - 右侧注解栏初始留空，显示提示文字："注解将在下一步生成..."

7. **输出**：
   - `<论文文件名>-cn.html`（保存到论文所在目录）
   - `smooth-white-plaster-wall.jpg`（复制纹理图片到同一目录）
   - 文件必须是自包含的（CSS 内嵌，KaTeX 通过 CDN 加载，纹理图片为外部文件）
   - **样式必须严格遵循 `references/design.md` 中的设计规范**，包括：
     - CSS 变量定义（`:root` 亮色 + `[data-theme="dark"]` 暗色）
     - Google Fonts 加载（Crimson Pro, Noto Serif SC, Atkinson Hyperlegible）
     - 纸张纹理叠加（`body::before` SVG 噪声）
     - 三栏布局（目录栏 240px / 正文 max 800px / 注解栏 300px）
     - 正文纸张效果（投影 + 边缘伪元素）
     - 侧栏毛玻璃效果（`backdrop-filter: blur(8px)`）
     - 亮/暗主题切换按钮和 localStorage 持久化
     - 响应式断点（1100px, 768px）

8. **Agent 完成后的检查清单**：
   - HTML 在浏览器中能否正常打开？
   - 目录链接是否都能正常跳转？
   - 图片是否都能显示（检查路径）？
   - 公式是否能渲染？
   - 三栏布局在不同宽度下是否正常？
   - 亮/暗主题切换是否正常工作？
   - 页面视觉效果是否符合"纸质论文阅读体验"（暖白纸张、衬线字体、纸张投影）？
   - **去重检查**：逐一检查每个 `<figure>` 之后的段落，是否存在 PDF 表格摊平产生的垃圾文本？判断标准：如果一个 `<p>` 中超过 50% 的 token 是数字（如 `89.48 25.77 31.7`），或内容是表格头碎片（如 `Model Token. Pile ppl ↓ acc ↑`），且对应的 `<figure>` 已包含该表格的图片，删除该段落

## 第 4 步：编写注解

### 目标
为论文中的重要概念、陌生术语编写高质量注解，插入到 HTML 右侧栏中。

### Agent 任务

启动一个独立的 Agent，完成以下工作：

1. **读取输入**：
   - `<论文文件名>-cn.html`（上一步生成的 HTML）
   - `translated/glossary.md`（术语表，作为注解素材）

2. **识别需要注解的内容**：
   - 遍历正文中每个章节，识别：
     - 领域外读者可能不理解的**专业术语**
     - 论文依赖的**重要背景知识**
     - 值得补充的**最新相关进展**
   - 注解原则：**宁缺毋滥**。只为真正重要、核心的概念添加注解。一篇论文通常 15-30 条注解即可，不要过度注解。

3. **编写注解内容**：
   - 对每个需要注解的概念，查询最新信息（使用 WebSearch）
   - 每条注解包含：
     - **概念解释**：这是什么？（2-4 句话，通俗易懂）
     - **为什么重要**：为什么这个知识点对理解论文很关键？（1-2 句）
     - **延伸阅读**：相关链接（可选）
   - 注解风格：精炼、准确，面向有一定基础但不一定是该领域专家的读者

4. **确定注解位置**：
   - 每个注解关联到正文中的一个段落（用段落的 ID 作为锚点）
   - 在正文对应位置插入 `📌` 标记（使用 `<span class="note-ref" data-note="note-XX">📌</span>`）
   - 在右侧栏创建注解卡片

5. **注解卡片 HTML 结构**：
   ```html
   <div class="annotation-card" id="note-XX">
     <div class="annotation-card-header" onclick="toggleAnnotation(this.parentElement)">
       <span class="annotation-card-title">
         <span class="annotation-card-icon">📌</span>
         概念名称
       </span>
       <span class="annotation-card-toggle">▼</span>
     </div>
     <div class="annotation-card-body">
       <p>注解解释文字...</p>
       <div class="annotation-links">
         <a href="https://..." target="_blank">🔗 延伸阅读：相关论文</a>
       </div>
     </div>
   </div>
   ```

6. **输出**：更新 `<论文文件名>-cn.html`

7. **Agent 完成后的检查清单**：
   - 注解数量是否适中（约 15-30 条）？
   - 核心概念是否都覆盖到了？
   - 注解中的链接是否可以访问？
   - 点击正文中的 📌 是否能定位到对应注解卡片？
   - 注解的内容是否存在明显的知识错误？

## 第 5 步：质量审查

### 目标
对照原文、译文和翻译质量标准，查缺补漏，将优化应用到最终 HTML。

### Agent 任务

启动一个独立的 Agent，完成以下工作：

1. **读取输入**：
   - `raw/manuscript.md`（原文）
   - `<论文文件名>-cn.html`（译文 HTML）
   - `references/translation-guide.md`（翻译质量手册）
   - `translated/glossary.md`（术语表）

2. **逐维度检查**：

   **完整性检查**（最重要）：
   - 原文的每个章节是否都有对应的译文？
   - 是否有段落被意外遗漏？
   - 所有图片是否都嵌入了？

   **准确性检查**（抽查）：
   - 随机抽取 10-15 句关键论述（摘要中的核心声明、方法的核心描述、结论中的主要发现）
   - 逐句对照原文，翻译是否准确？
   - 是否有明显的误译？

   **术语一致性检查**：
   - 对照术语表，全文术语翻译是否一致？
   - 同一英文术语是否出现了两种不同译法？

   **可读性检查**：
   - 是否存在明显翻译腔的句子？（如"被...所"、"进行了一个...的操作"）
   - 长句是否拆分为合理的中文短句？

   **注解正确性检查**：
   - 注解中的概念解释是否有事实错误？
   - 延伸阅读链接是否有效？

   **格式完整性检查**：
   - 所有图片的 src 路径是否正确？
   - TOC 目录链接是否都有效？
   - KaTeX 公式是否正常渲染？
   - HTML 结构是否完整？
   - **表格垃圾文本检查**（最终防线）：逐页浏览 HTML，检查每个 `<figure>` 附近是否存在 PDF 表格摊平产生的垃圾文本。判断标准：
     - 连续多行纯数字（如 `89.48 25.77 31.7`）
     - 表格头碎片（如 `Model Token. Pile ppl ↓ acc ↑`）
     - 图表轴标签碎片（如 `2 × 101`、`Perplexity (log scale)`）
     - 图表图例碎片（如 `Hyena RWKV Transformer RetNet`）
     - 如果发现，直接在 HTML 中删除这些段落。已在 `<figure>` 图片中显示的数据不需要文本版本

3. **修复策略**：
   - **能自动修复的**：直接在 HTML 中修改（如术语不一致、翻译腔、格式问题）
   - **有疑问的**：在 `translated/review_report.md` 中记录，标记为需要人工确认

4. **输出**：
   - 更新 `<论文文件名>-cn.html`（应用修复）
   - `translated/review_report.md`（审查报告）

5. **审查报告格式**：
   ```markdown
   # 翻译审查报告

   ## 已自动修复
   - [行号/位置] 问题描述 → 修复内容
   - ...

   ## 需要人工确认
   - [行号/位置] 问题描述：为什么需要确认
   - ...

   ## 总体评价
   - 完整性：✅ / ⚠️ / ❌
   - 准确性：✅ / ⚠️ / ❌
   - 术语一致性：✅ / ⚠️ / ❌
   - 可读性：✅ / ⚠️ / ❌
   - 注解正确性：✅ / ⚠️ / ❌
   ```

## 设计决策说明

执行阶段二时，遵循以下原则：

1. **学术严谨优先**：翻译准确度高于可读性，宁可保留学术腔也不曲解原意
2. **KaTeX 渲染公式**：利用 CDN 加载 KaTeX，轻量且快速
3. **注解宁缺毋滥**：15-30 条注解覆盖核心概念即可
4. **自动修复优先**：审查阶段能自动修的直接修，有疑问的标记出来让人工决定
5. **HTML 命名**：使用 `<论文文件名>-cn.html` 格式，与原始 PDF 放在同一目录
6. **中间产物可检**：每步完成后暂停，让用户检查 `raw/`、`translated/` 中的产物
