# 代码逻辑教学可视化场景

## 场景说明

将一段晦涩的代码（控制流复杂、隐式状态变量多、数据变换路径长）转化为**交互式执行模拟器**。读者通过分步回放一个具体的真实执行场景，观察数据如何随代码流动。

**核心哲学**：不画静态流程图（只展示结构，无用），要做执行回放（展示数据随时间的变化轨迹）。

## 适用场景

| 适用 | 不适用 |
|------|--------|
| 循环/条件/回调密集的引擎代码 | 纯 CRUD 的简单代码 |
| 数据流经过多层变换的管道 | 一目了然的配置/常量文件 |
| 含隐式状态变量的控制逻辑 | 纯算法函数（适合动画而非回放） |
| 需要理解"为什么是这个结果"的代码 | 只是想知道 API 怎么调用的代码 |

## 技术栈

- 纯 HTML + Vanilla JS，单文件
- **不使用**任何 CDN 依赖（D3、React 等都不需要）
- **不需要** `data.json`（数据直接内联为 JS 对象——执行步骤本身就是数据）
- 深色主题（`#0d1117` 背景），GitHub 风格配色

## 数据格式规范

### 不适用 data.json

与其他场景不同，代码逻辑可视化的"数据"不是外部采集的结构化数据，而是一组**手工设计的执行步骤**。这些步骤直接写在 HTML 的 `<script>` 中，不在单独的 JSON 文件中。

### 步骤数据结构

```js
const steps = [
  {
    id: 1,
    title: '入口：函数名() 做什么',
    desc: 'HTML 格式的详细说明，可用 <code>、<b>、<br> 标签',
    codeFile: '路径/到/源文件.ts',
    codeLines: '31-54',
    codeSnippet: [
      'export function foo(',
      '  arg1: Type,',
      '): ReturnType {',
      '  const result = ...',
      '}',
    ],
    // 该步骤完成时展示的消息列表
    msgs: ['msg_key_1', 'msg_key_2'],
    // 本条步骤新增的消息 ID
    newIds: ['msg_key_2'],
    // 循环状态
    loopState: { outer: false, inner: false, phase: null },
    // 状态机阶段：当前活跃(蓝色脉冲) / 已完成(绿色) / 跳过(灰色删除线)
    phasesActive: ['phase-llm'],
    phasesDone: ['phase-turn-start'],
    phasesSkipped: ['phase-inject'],
    innerRound: 1
  }
];
```

### 循环变量值映射

单独定义一个数组，记录每一步的隐式状态变量：

```js
const loopVarValues = [
  { hasMore: null, pending: null, firstTurn: null },   // 步骤 1
  { hasMore: true,  pending: 0, firstTurn: true  },    // 步骤 2
  // ... 每步对应一项
];
```

变量值类型：
- `null` → 显示 `—`（未进入该阶段）
- `boolean` → 绿色 `true` / 红色 `false`
- `number` → 蓝色数字 / 灰色 0

### 模拟消息数据

```js
const MSG_USER = {
  role: 'user',
  content: '具体内容，使用真实文件名和数据'
};
const MSG_ASSISTANT = {
  role: 'assistant',
  content: [
    { type: 'text', text: '...' },
    { type: 'toolCall', id: 'tc_001', name: '真实工具名', arguments: { ... } }
  ],
  stopReason: 'toolCalls'
};
const MSG_MAP = {
  msg_key_1: MSG_USER,
  msg_key_2: MSG_ASSISTANT,
  // ...
};
```

## 实现要点

### 确定执行步骤（最关键）

1. 选一个**具体真实的场景**（一个输入 + 一条完整路径）
2. 拆成 **8-12 个"关键时刻"**（<6 太粗，>15 太细）
3. 关键时刻 = 数据状态发生可观察变化的瞬间

### 布局：三栏等宽

| 左栏 | 中栏 | 右栏 |
|------|------|------|
| 变量指示器 | 消息时间线 | 步骤详情 |
| 循环状态机 | 消息卡片列表 | 代码片段 |

### 变量指示器

放在左栏顶部。用 `var-row` 展示每个隐式状态变量，值变化时加 150ms `scale(1.15)` 脉冲动画。布尔值用绿/红色高亮区分。

### 代码片段

- **括号必须闭合**：每步的 codeSnippet 拼接后 `{` 和 `}` 数量必须相等
- **只做关键字高亮**：`function/async/await/const/let/if/else/return/try/catch`，红色 `#ff7b72`
- **注释高亮**：`//` 开头，灰色 `#8b949e`
- **禁止字符串高亮**：字符串正则会与 HTML `<span>` 标签冲突

### 收束：最后一步必须有回顾面板

```
入口 → 外层 → 内层R1 → 🔧工具 → 内层R2 → ✓出口
```

总结关键数字和核心洞见。

### 快捷键

- `←` `→`：上一步/下一步
- 空格：播放/暂停
- `R`：重置

## 子 Agent 架构（本场景的特殊调整）

代码逻辑可视化**不需要数据准备 sub-agent**——数据不是从外部搜索采集的，而是分析源码后手工设计的执行步骤。流程调整为：

```
主 agent
├── 读取源码、理解逻辑、设计执行步骤（自己执行）
├── 设计方案并确认
└── 单 sub-agent ← 负责编写完整 HTML + 启动服务器 + 冒烟测试
```

主 agent 需要把设计好的执行步骤数据（完整的 steps 数组定义）直接传给实现 sub-agent。

## ⚠️ 已知坑点

| 坑点 | 表现 | 解决方案 |
|------|------|---------|
| 代码片段括号不闭合 | 看起来像 bug，读者困惑 | 每步 codeSnippet 写入后验证 `opens===closes` |
| 字符串高亮正则破坏 HTML | 显示 `<span class="<span>">"kw"</span>` | 禁止字符串高亮，只做关键字和注释 |
| D3/流程图 | 只展示结构不展示数据，无教学价值 | 做执行模拟器而非静态流程图 |
| 步骤太多（>15） | 读者疲劳，失去全局视角 | 合并相邻步骤，控制在 8-12 个 |
| 无收束 | 碎片化记忆 | 最后一步必须给出完整时间线回顾 |
| 占位数据 | `foo`/`bar` 没有教学意义 | 用真实文件名、真实工具名、合理返回内容 |
| 缺少状态变量展示 | 读者要脑补数据变化 | 变量指示器实时显示每一步的隐式状态值 |
| `codeSnippet` 数组末尾多 `],` | JS 语法错误，页面白屏 | 写入后用 Node.js `new Function()` 验证语法 |
