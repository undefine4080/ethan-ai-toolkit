# 大道至简 / 反绕弯路

简洁是工程师的最高品味。但"简洁"不是"短"，而是**没有多余**。一段 100 行的清晰代码比 30 行的精巧代码更简洁。

---

## 核心判断问句

1. **这段逻辑能不能更直接？** 能不能少一个中间变量、少一层嵌套、少一次转换？
2. **一个新人读这段代码，需要跳几个心智跳板？** 跳板越多越糟。
3. **这里用的模式（策略、工厂、观察者等），对应的问题真的需要它吗？**
4. **这段代码的圈复杂度有没有失控？** if / else / && / || / 三元 / try 互相嵌套超过 3 层就是警报。
5. **能不能用早退出（early return / guard clause）把嵌套压平？**

---

## 常见的"绕弯路"模式

### 1. 无意义的中间变量

```
// 绕
const isUserAdmin = user.role === 'admin';
if (isUserAdmin) { ... }

// 直接（当 isUserAdmin 只用一次）
if (user.role === 'admin') { ... }
```

命名变量是为了让语义更清晰。如果变量名就是条件的复述（`const isFoo = x === 'foo'`），且只用一次，不如直接写条件。

**反例外**：如果条件复杂或有复用，提取命名变量反而是简洁——这种不要误判。

### 2. 深层嵌套（箭头代码）

```
if (a) {
  if (b) {
    if (c) {
      // 真正的逻辑
    }
  }
}
```

几乎总是可以用**早退出**压平：

```
if (!a) return;
if (!b) return;
if (!c) return;
// 真正的逻辑
```

### 3. 不必要的 async / await 链

看到 `await` 后立即 `return` 这种链式，多半可以直接返回 Promise。但注意：在 try/catch 里 `await` 是必要的，不要教条。

### 4. 状态机被写成条件判断迷宫

多个布尔变量（`isLoading`、`isError`、`isEmpty`、`isSuccess`）互相组合判断。这是**该用状态机的信号**：一个 `status` 字段比多个布尔简洁得多。

### 5. 过度链式 / 过度 functional

```
items.filter(...).map(...).reduce(...).filter(...).map(...)
```

链超过 3-4 级时，拆成命名良好的中间步骤反而更清晰。"函数式一条龙"不是目的，清晰才是。

### 6. 把简单数据转换写成大套路

一次性的 `obj => ({ ... })` 映射，非要抽成一个 `transformer` 类。**一次性的转换就写在原地**，不要为了"解耦"强行抽函数。

## 圈复杂度的直觉标尺

不必精确计算，凭感觉：

| 表现 | 复杂度感知 |
|---|---|
| 函数超过 50 行 | 警报 |
| 嵌套超过 3 层 | 警报 |
| 一个函数里 if / else / 三元超过 5 个 | 警报 |
| 一个函数同时处理：参数校验 + 业务分支 + 数据转换 + 副作用 | 几乎一定要拆 |

**但注意**：不要机械地"函数一定要短"。**内聚 > 短**。一个 80 行但职责单一清晰的函数，好过 8 个互相耦合的 10 行函数。

---

## 关于"抽象 vs 重复"的分寸

很多人会问："这段代码出现了两次，要不要抽？"

经验法则：

- **出现 2 次**：先不抽，标个 TODO
- **出现 3 次**：可以抽了
- **看起来像重复但实际语义不同**：**不要抽**。强行抽会造成"假复用"，以后只要有一个分支变化，就得加参数，最后抽象比原来还乱

> 重复是便宜的，错误的抽象是昂贵的。（The wrong abstraction is more expensive than duplication.）

---

## 好简洁的正向特征

- 读一段代码从上到下不需要大量跳转就能理解
- 变量名即文档，不用看实现就能猜意图
- 没有"为什么这样写"的疑问（或者有注释解释为什么）
- 删一行就少一个功能，加一行就多一个功能——没有冗余

## 严重度定级参考

| 现象 | 建议严重度 |
|---|---|
| 圈复杂度爆炸的核心业务函数 | 🟡 Major |
| 该用状态机的布尔迷宫（已导致 bug 或难以维护） | 🟡 Major |
| 局部的深层嵌套、可压平 | 🟢 Minor |
| 链式过长、可读性稍差 | 🟢 Minor |
| 无意义中间变量 | 💭 Nit |
