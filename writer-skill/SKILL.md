# Writer Skill — 深度中文文章写作

## 核心原则

**充分的人机沟通 > 全自动生成**。全自动产出的内容价值极低，每个阶段都必须与用户充分对话、确认后再推进。宁可多问十个问题，也不要凭空假设。

## 写作流程总览

```
阶段 1：选题深访  →  [用户确认大纲]
阶段 2：素材搜集  →  [用户确认素材]
阶段 3：正式写作  →  [用户过目初稿]
阶段 4：质检核查  →  [用户复核 checklist]
阶段 5：润色发布  →  终稿
```

每个阶段结束后**必须暂停**，向用户展示成果，等待明确确认后才进入下一阶段。

## 阶段 1：选题深访（对话提问）

**激活 skill 后，不要立刻动手写任何内容。** 先通过多轮对话把写作意图挖透。

提问之前：确保你知道用户给出的文章标题的含义是什么，如果你不清楚，那么就在线查一下，先有个背景信息

提问策略：分批提问，每次 2-3 个问题，根据回答追问，直到对以下维度有清晰认知：

- **核心信息**：这篇文章要传递给读者什么？读者读完能得到什么？
- **目标读者**：谁会读这篇文章？他们的背景和知识水平如何？
- **文章深度**：科普入门？实战指南？深度分析？观点评论？
- **核心观点**：作者有什么独特视角或判断？（无观点 = 无价值）
- **关键知识点**：文章必须讲清楚哪些内容？
- **需要回避的**：有什么禁区、误区或需要特别注意的角度？
- **参考标杆**：有没有觉得写得好的类似文章可以参考？
- **文章长度**：预期字数？（参考：3000字入门、5000字深度、8000字+长文）
- **发布平台**：微信公众号？掘金？知乎？少数派？（影响排版和风格）

提问原则：**不要机械的全部提出以上列出的问题，而是要根据用户的文章主题进行思考，哪些因素是你还很模糊的，哪些因素对文章的质量至关重要，这些都是有必要的问题，你应该只提必要的问题**

深访完成后，输出**选题确认单**：

```
【选题确认单】
面向读者：___
核心信息：___
能解决的问题：___
文章类型：___
核心观点：___
预计字数：___
发布平台：___

【初版大纲】
一、___
二、___
三、___
...
```

**等待用户确认或修改大纲，确认后进入阶段 2。**

### 大纲交付规范

- 在与用户确认好大纲之后，你还需要进行一遍检查确认，核实你编写的大纲中的每个要点是否成立，是否真实。
- 确保每个要点都是有据可查，而不是你根据自身知识编造出来的

---

## 阶段 2：素材搜集

根据大纲拆解出 **3-5 个搜索角度**，用多个子 agent 并行调用 **agent-browser** 搜集素材。

**搜索策略：**

- 优先权威来源：官方文档、学术论文、知名媒体、行业报告
- 注意时效性：优先近 1-2 年内的内容
- 多角度覆盖：支持观点的、反驳观点的、数据佐证的都要找
- 中英文都搜，优先搜索英文资料（多而全），其次才是中文资料（质量不高）作为补充
- 素材最少 8 个，最多 40 个，视情况合理决策

**素材保存规范：**

为每篇文章创建独立工作目录，详见 `references/file-structure.md`。

每条素材保存为单独文件，包含：

- 来源 URL
- 发布时间
- 核心摘要（AI 提炼，200字以内）
- 关键引用（可直接用在文章中的数据、观点、表述）

降级方案：若无法保存原文，至少保存链接 + 摘要。

**素材汇总报告格式：**

```
【素材汇总报告】

## 搜集概况
- 搜集角度：N 个
- 有效素材：N 篇
- 时效分布：___
- 来源类型：___

## 素材分类

### 支撑核心观点
- [素材1] 来源、摘要、关键引用
- ...

### 数据与事实
- [素材1] 来源、数据点
- ...

### 不同视角 / 反驳观点
- [素材1] 来源、摘要
- ...

## 素材缺口
- 还缺少哪方面的支撑：___
- 建议补充搜索方向：___
```

**等待用户确认素材是否充分，确认后进入阶段 3。**

---

## 阶段 3：正式写作

基于用户确认的大纲和素材，开始写作。

**写作规范：**

- 有观点、有论据、有逻辑，拒绝"正确的废话"
- 每个核心观点都要有素材支撑
- 数据引用必须标注来源
- 代码示例（如有）必须真实可运行
- 避免过度使用 AI 写作特征（em dash、排比、陈词滥调）

**输出：** 将初稿保存为工作目录下的 `draft.md`，同时在对话中展示全文。

**等待用户过目初稿，收集修改意见，确认后进入阶段 4。**

---

## 阶段 4：质检核查

对初稿进行系统性自查，输出 **质检 checklist**，供用户人工复核。

**自查维度：**

```
【质检 checklist】

## 事实核查（用户必须逐条核实）
- [ ] [第X段] 数据"___" — 来源：___ — 待核实
- [ ] [第X段] 观点"___" — 来源：___ — 待核实
- [ ] [第X段] 引用"___" — 来源：___ — 待核实

## 来源与权威性自查（AI 已检查）
- [ ] 文章中每一个"规范"或"框架"，是否交代了出处？
      区分清楚：官方文档规定 / 社区实践惯例 / 作者个人经验
- [ ] 所有引用来源是否已格式化为可点击的 Markdown 链接？
      格式：[描述文字](URL)，让读者可以直接追溯

## 论断强度自查（AI 已检查）
- [ ] 扫描文中所有"应该/不应该/一定/不能/最好/不要"等绝对表述
      每一条是否有充分依据？还是作者主观判断？
      主观判断须标注"作者认为"或降级措辞（"通常"、"在多数情况下"）
- [ ] 是否有对读者可能存疑的结论，但文章没有提供充分解释？

## 逻辑自查（AI 已检查）
- [ ] 论点是否有充分论据支撑
- [ ] 是否有前后矛盾的表述
- [ ] 因果关系是否成立

## 内容自查（AI 已检查）
- [ ] 错别字、笔误
- [ ] 明显语病
- [ ] 代码示例是否正确（如有）

## 结构自查（AI 已检查）
- [ ] 开头是否足够吸引人
- [ ] 结尾是否有明确收尾
- [ ] 各段落衔接是否流畅

## 内容重复自查（AI 已检查，发现问题必须先修订再提交）
- [ ] 逐节扫描：每个小节的核心内容是否唯一？是否有两个或以上小节在传达相同或高度相似的信息？
- [ ] 列出所有疑似重复的段落对：[章节A] vs [章节B]，描述重复点
- [ ] 检查"引言/背景"与正文各节之间是否存在大段内容重复（预告式重复）
- [ ] 检查"总结/结尾"是否只是对正文的逐点复述，而非升华或收拢

**⚠️ 若发现重复，不得直接提交 checklist 让用户审核。必须先修订文章消除重复，再更新 `draft.md`，然后在 checklist 中注明"已修订：[修订说明]"。**
```

**将 checklist 保存为 `checklist.md`，等待用户复核通过后进入阶段 5。**

---

## 阶段 5：润色发布

调用 **chinese-humanizer** 对通过质检的文章进行润色，消除 AI 写作痕迹，让文章读起来更有人味。

润色完成后，将终稿保存为 `[正式文章标题].md`。

向用户展示终稿，任务完成。
